# Pocket Allowance MVP 仕様

## 1. 目的

Pocket Allowance MVP は、家庭内でポイント制のお小遣い運用を試験導入するための Web アプリである。親と子が同じ世帯に参加し、月ごとのルールに基づいてポイントを記録し、月末に確定したポイントを円換算して翌月のお小遣いの参考値とする。

## 2. 利用者

- 親
  - 世帯の作成
  - 子どもの管理
  - ルールの登録
  - ポイントの記録
  - 月締め
  - 締め後の修正
- 子
  - 世帯への参加
  - 自分に紐づくルールの確認
  - ルール承認
  - ポイント履歴の確認

## 3. 前提ルール

- MVP では 1 ユーザーは 1 世帯のみに所属できる
- 1 世帯あたり親権限は最大 2 名まで
- 1 世帯には複数の子どもを所属できる
- 親子の関係は多対多で管理する
- 親のみがポイント記録と月締めを実行できる
- 子どもごとに 1pt あたりの円換算レートを持つ

## 4. 認証と初期登録

- 認証方式は Supabase Auth の Magic Link とする
- Magic Link メールの件名には必ず「ポイント制お小遣いアプリ」を含める
- 推奨件名は `【ポイント制お小遣いアプリ】ログインリンク` とする
- 初回ログイン時に未登録ユーザーは以下を入力する
  - 表示名
  - ロール
- 親を選んだユーザーは世帯を新規作成する
- 子を選んだユーザーは親から共有された招待コードを入力して世帯に参加する

## 5. 世帯と招待

- 世帯は親ユーザーが作成する
- 世帯作成時に招待コードを自動発行する
- 子ユーザーは招待コードを入力して世帯に参加する
- 親ユーザーは同一世帯内で最大 2 名まで登録できる
- 2 人目の親も同じ招待コードで参加できる

## 6. 親子リンク

- 親子リンクは世帯内メンバー間で明示的に作成する
- 1 人の親が複数の子どもとリンクできる
- 1 人の子どもが複数の親とリンクできる
- ポイント記録、ルール登録、月締めはリンク済みの子どもに対してのみ実行できる

## 7. ルール管理

- 親は子どもごと、月ごとに最大 20 件までルールを登録できる
- ルールは以下を持つ
  - 対象月
  - ラベル
  - ポイント値
  - 状態
- ルール状態
  - `draft`
  - `pending_child_approval`
  - `pending_parent_approval`
  - `active`
  - `rejected`
- ルール作成直後は `pending_child_approval`
- 子が承認すると `pending_parent_approval`
- 親が承認すると `active`
- 却下されたルールは `rejected`
- `active` のルールだけがポイント記録に利用できる

## 8. ポイント記録

- 親のみがポイントを記録できる
- 記録項目
  - 対象日
  - 対象ルール
  - 加点または減点
  - メモ
- ルールに紐づく記録を基本とする
- 追加ボーナスや特別減点のために任意メモ付きの手入力記録も許可する
- 締め済み月には子は編集不可
- 締め済み月でも親は修正可能
- 締め済み月を親が修正した場合は操作ログを必ず保存する

## 9. 月締め

- 親のみが月締めを実行できる
- 月締め対象は子ども単位、月単位とする
- 月締め時に以下を集計する
  - 合計ポイント
  - 円換算額
- 未承認ルールは月締め対象に含めない
- 月締め後は月次サマリーを `closed` とする
- 締め後も親は修正できるが、再計算を行い最新の確定値に更新する
- 締め後修正時は操作ログに以下を残す
  - 操作種別
  - 対象テーブル
  - 対象 ID
  - 実行者
  - 差分概要
  - 実行日時

## 10. 通知

- MVP では未承認ルール件数をバッジ表示する
- Push 通知やメール通知は対象外

## 11. 画面要件

- トップページ
  - 未ログイン時は Magic Link ログイン
  - 初回登録時は表示名 / ロール / 招待コード入力
  - ログイン済みはダッシュボード
- 子ども一覧
  - 親のみ表示
  - リンク済みの子ども一覧
  - 未承認ルール数と今月の概算表示
- ルール管理
  - 対象月切替
  - ルール作成
  - 承認操作
  - 状態表示
- ポイント管理
  - 日付選択
  - ルール選択による記録
  - 手入力ボーナス / 減点
  - 月次履歴
  - 月締め

## 12. 非機能要件

- Web ブラウザで利用できること
- Docker Compose で起動できること
- 将来の PWA 化を見据え、画面はモバイル幅でも破綻しないこと
- 認証済み操作は Supabase RLS で保護すること
